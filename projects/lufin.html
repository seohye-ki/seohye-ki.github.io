02. TRANSACTION & CONCURRENCY

"데이터는 정직해야 하니까,
흐름보다 먼저 정합성을 설계했습니다."

ItemPurchaseService.java 
@Transactional
@Lock(LockModeType.PESSIMISTIC_WRITE) // 비관적 락(Pessimistic Lock)
public void purchaseItem(Long itemId, Long userId) {
    Item item = itemRepository.findByIdWithLock(itemId);
    
    // 재고 확인 및 차감 (동시성 제어 핵심 구간)
    if (item.getStock() <= 0) {
        throw new OutOfStockException();
    }
    item.decreaseStock();
    
    // ... 결제 로직 수행
}
🛡️ 비관적 Lock 도입

선착순 아이템 구매, 자동이체 등 충돌 빈도가 높은 로직에 Pessimistic Lock을 적용하여 데이터 무결성을 절대적으로 보장했습니다.

📊 시스템 영향도 평가

기능 수정 전 항상 리스크를 분석하고, 도메인 간의 데이터 흐름을 추적하여 사이드 이펙트를 최소화했습니다.
