04. TRANSACTION & CONCURRENCY

데이터는 정직해야 하니까,
정합성을 설계했습니다

ItemRepository.java 
@Lock(LockModeType.PESSIMISTIC_WRITE)
@QueryHints({
    @QueryHint(name = "jakarta.persistence.lock.timeout", value = "1000")
})
@Query("SELECT i FROM Item i WHERE i.id = :itemId")
Optional<Item> findByIdWithPessimisticLock(@Param("itemId") Integer itemId);
🛡️ 비관적 Lock (Pessimistic Lock)

선착순 아이템 구매와 같이 충돌 빈도가 높은 핵심 로직에 DB 수준의 Lock을 적용하여, 동일 자원에 대한 동시 접근을 원천적으로 차단하고 데이터 정합성을 보장했습니다.

⏱️ Lock Timeout 설정

무한 대기(Deadlock)를 방지하기 위해 1초(`1000ms`)의 타임아웃을 설정하여 시스템의 가용성과 안정성을 동시에 확보했습니다.

AOP 권한 제어

RoleCheckAspect.java 
@Aspect @Component
public class RoleCheckAspect {
    @Before("@annotation(TeacherOnly)")
    public void checkTeacherRole() {
        Member member = getCurrentUser();
        if (member.getMemberRole() != MemberRole.TEACHER) {
            throw new BusinessException(ErrorCode.REQUEST_DENIED);
        }
    }
}
횡단 관심사 분리의 성과
  • 코드 응집도 향상: 수십 개의 API 컨트롤러에서 권한 체크 로직을 완전히 제거
  • 유지보수 용이성: 권한 로직 변경 시 Aspect 클래스 한 곳만 수정
  • 실수 방지: 어노테이션 하나로 누락 없는 보안 정책 적용 가능
